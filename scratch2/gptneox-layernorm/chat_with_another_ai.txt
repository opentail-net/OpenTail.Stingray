there are a couple of important details the other AI has compressed away.

The biggest correction is this: Pythia/GPT-NeoX does not send attention and FFN the exact same normalized tensor. Both branches read the same incoming residual x, but through two different LayerNorms with separate learned weights and biases:

attn = Attention(LayerNorm1(x))
ffn  = MLP      (LayerNorm2(x))
out  = x + attn + ffn

That is the GPT-NeoX parallel-residual structure. Hugging Face's reference implementation does exactly this.

1. The new LayerNorm primitive

This is the largest genuinely new numerical primitive if your engine currently only has RMSNorm.

RMSNorm essentially does:

rms = sqrt(mean(x²) + eps)
y[i] = x[i] / rms * weight[i]

LayerNorm does:

mean = mean(x)

variance =
    mean((x[i] - mean)²)

invStd =
    1 / sqrt(variance + epsilon)

y[i] =
    ((x[i] - mean) * invStd)
    * gamma[i]
    + beta[i]

The gamma is the LayerNorm weight and beta is the LayerNorm bias.

Critically, variance is the population/biased variance:

sum((x - mean)^2) / N

not:

sum((x - mean)^2) / (N - 1)

That matches PyTorch LayerNorm.

For Pythia:

N = 768
epsilon = 1e-5

for every transformer LayerNorm.

I would make the engine API generic

Something conceptually like:

LayerNorm(
    input,
    weight,
    bias,
    output,
    hiddenSize,
    epsilon);

rather than a PythiaLayerNorm().

And make bias optionally absent, because that makes the primitive useful for other architectures too.

CPU implementation

For correctness-first implementation I would use a two-pass algorithm:

pass 1:
    mean = sum(x) / N

pass 2:
    variance = sum((x - mean)^2) / N

pass 3/vector loop:
    output =
        (x - mean)
        * rsqrt(variance + epsilon)
        * gamma
        + beta

You can merge the second/output passes only if you're careful.

I'd accumulate statistics in float at minimum even if the underlying weights are F16. Don't prematurely produce some heroic AVX2 fused kernel until reference parity works.

Then AVX2 optimisation is straightforward because 768 is comfortably vectorisable.

3. The parallel residual restructure

This is architecturally more significant than the LayerNorm kernel.

Most Llama-style engines effectively do something like:

x = x + Attention(Norm(x))
x = x + MLP(Norm(x))

The MLP therefore receives the post-attention residual stream.

Pythia does not.

It does:

residual = x

a = Attention(
      InputLayerNorm(residual)
    )

m = MLP(
      PostAttentionLayerNorm(residual)
    )

x = residual + a + m

Hugging Face implements the parallel case exactly as:

attention(input_layernorm(hidden_states))

mlp(post_attention_layernorm(hidden_states))

hidden_states =
    mlp_output
    + attn_output
    + hidden_states

That means your execution engine needs to preserve x until both branches have completed.

Don't accidentally implement this
x1 = x + attention(...)
ffn = MLP(LN(x1))
out = x1 + ffn

That is ordinary sequential pre-norm and will produce completely wrong logits.

Also don't implement this
normed = LayerNorm(x)

attn = Attention(normed)
ffn  = MLP(normed)

because GPT-NeoX has two independently parameterised LayerNorms.

It's:

attnInput = LN1(x)
ffnInput  = LN2(x)

They merely have the same source residual.

4. The FFN is simpler than Llama-style gated FFNs

This part really is relatively easy.

A Llama/SwiGLU-style block looks roughly like:

gate = SiLU(Wgate x)
up   = Wup x

hidden = gate * up

out = Wdown hidden

GPT-NeoX/Pythia is plain old:

hidden =
    GELU(
        Wup x + bUp
    )

out =
    Wdown hidden + bDown

Hugging Face's GPT-NeoX MLP has exactly two Linear layers surrounding the activation.

Dimensions for 160M are:

768
 ↓
Linear 768 → 3072
 ↓
GELU
 ↓
Linear 3072 → 768

No gate.

No Hadamard multiply.

No SiLU.

No second input projection.

5. FFN bias is important

The tensors are:

gpt_neox.layers.N.mlp.dense_h_to_4h.weight
gpt_neox.layers.N.mlp.dense_h_to_4h.bias

gpt_neox.layers.N.mlp.dense_4h_to_h.weight
gpt_neox.layers.N.mlp.dense_4h_to_h.bias

The GPT-NeoX checkpoints explicitly contain those bias tensors.

So mathematically:

u = Wup × x
u += bUp
u = GELU(u)

y = Wdown × u
y += bDown

Notice where bUp goes:

GELU(Wx + b)

not:

GELU(Wx) + b

That distinction matters.

I would strongly consider making this a generic engine facility:

Linear(weight, optionalBias)

rather than adding Pythia-specific bias handling.

That immediately helps other older transformer families.

6. GELU needs the correct variant

The config says:

"hidden_act": "gelu"

That normally means the standard GELU:

GELU(x) = x Φ(x)

equivalently:

0.5 * x *
(1 + erf(x / sqrt(2)))

rather than automatically assuming the commonly used tanh approximation. PyTorch distinguishes exact GELU from approximate="tanh".

For initial bring-up, I would use the exact/reference GELU.

Once logits match, benchmark an approximation if you want.

For a 160M diagnostic model, correctness is enormously more useful than shaving microseconds here.

8. There is an even more important thing to verify: GPT-NeoX QKV layout

This is the thing most likely to produce a model that loads perfectly and outputs complete rubbish.

GPT-NeoX uses one fused projection:

768 → 2304

because:

2304 = 12 heads × 3 × 64

But the output is interpreted per head.

Hugging Face reshapes it effectively as:

[..., 12 heads, 3 * 64]

and then splits that last dimension into:

Q 64
K 64
V 64

In other words the logical arrangement is:

head 0:
    Q0[64]
    K0[64]
    V0[64]

head 1:
    Q1[64]
    K1[64]
    V1[64]

...

head 11:
    Q11
    K11
    V11

rather than necessarily:

all Q heads
all K heads
all V heads

If your current inference engine assumes the latter representation, you need either:

load-time QKV repacking

or:

GPT-NeoX-aware QKV extraction

I would strongly favour load-time repacking if it allows the hot attention kernel to remain generic.

This deserves its own diagnostic.

9. Pythia has partial RoPE — only 25% of each head

This also needs checking because it is unusual compared with modern Llama-family models.

Head dimension:

768 / 12 = 64

Pythia:

rotary_pct = 0.25

therefore:

rotaryDim = 64 × 0.25 = 16

Only:

Q[..., 0..15]
K[..., 0..15]

get RoPE.

Dimensions:

16..63

pass through untouched.

And GPT-NeoX uses the rotate-half style over those dimensions:

[x0 ... x7 | x8 ... x15]

       ↓

[-x8 ... -x15 | x0 ... x7]

rather than blindly assuming whatever Llama RoPE layout your existing kernel uses. The reference GPT-NeoX implementation explicitly performs this half-rotation.

So I would add a requirement:

Verify existing RoPE supports GPT-NeoX partial rotary + NeoX rotation convention.

The other AI hasn't mentioned this, which may mean it already verified your current code can do it.

But I wouldn't assume that.

10. Normal attention itself is pleasantly boring

Otherwise Pythia's attention is straightforward.

For 160M:

12 query heads
12 key heads
12 value heads

headSize = 64

GQA = no
MQA = no

scale =
    1 / sqrt(64)
  = 1 / 8
  = 0.125

It uses ordinary causal self-attention and normal K/V caching. The GPT-NeoX reference multiplies QKᵀ by the inverse square-root head scale before softmax.

So if your current MHA implementation already works, this shouldn't require a fundamentally new attention kernel.

12. Final LayerNorm must change too

It's easy to implement the new LayerNorm inside the transformer and accidentally leave the final norm using RMSNorm.

GPT-NeoX does:

12 layers
↓
final_layer_norm
↓
LM head

and that final norm is also nn.LayerNorm, not RMSNorm.

It therefore requires:

weight[768]
bias[768]
epsilon = 1e-5
13. The complete layer, mathematically

This is essentially the implementation spec I'd give the AI.

For layer L, incoming residual x:

# ATTENTION BRANCH

a0 =
    LayerNorm(
        x,
        ln1.weight,
        ln1.bias,
        eps = 1e-5
    )

qkv =
    Wqkv × a0
    + bqkv

split/repack qkv according to GPT-NeoX layout

apply RoPE to first 16 dimensions
of each Q/K head only

scores =
    Q × Kᵀ / sqrt(64)

scores =
    causal_mask(scores)

probs =
    softmax(scores)

attn =
    probs × V

attn =
    Wo × attn
    + bo


# MLP BRANCH

m0 =
    LayerNorm(
        x,                 ← ORIGINAL x
        ln2.weight,
        ln2.bias,
        eps = 1e-5
    )

m1 =
    Wup × m0
    + bUp

m2 =
    GELU(m1)

mlp =
    Wdown × m2
    + bDown


# PARALLEL RESIDUAL

xNext =
    x + attn + mlp

That is the essential Pythia transformer block.

After layer 11:

x =
    LayerNorm(
        x,
        final.weight,
        final.bias,
        1e-5
    )

logits =
    embed_out.weight × x

15. How I'd actually build this

The other AI's “build it now” recommendation is sensible, but I'd divide the work slightly differently.

I would do it in this order:

Generic Linear bias support

MatMul + optional bias

Unit-test it.

Generic LayerNorm

mean + population variance + gamma + beta

Unit-test against PyTorch.

Linear+bias → GELU → Linear+bias
