# TensorShape hardening, and follow-ups from the SharpMind review — plan

Status 2026-11-09. Source of the review: the comparison with SharpMind (`examples/SharpMind/SharpMind`) supplied by the owner. This plan covers one system: the `TensorShape` descriptor in `OpenTail.Stingray.Core`.

## 1. Scope from the review

| Review item | Decision | State |
|---|---|---|
| R1. Replace the unsafe `TensorShape` representation | **Do it** (the review's recommendation) | This plan |
| R2. Investigate CPU MoE expert residency, measure first | Investigate only | Not started. Needs a real MoE checkpoint and memory-pressure runs. No MoE GGUF was found under the repo's `models/` directory by name. |
| R3. Review tensor-view opportunities | Low priority | Not started |
| R4. BERT-family encoder support | Optional, owner decision | Not started |
| Excluded by the review: KV cache, JigSaw IL emission, training/autograd, parallel loading | Not for Stingray | Not applicable |

## 2. The review's claims, checked against code

| Claim | Result |
|---|---|
| Stingray's `TensorShape` is `public readonly record struct TensorShape(long[] Dims)` | **True.** `src/OpenTail.Stingray.Core/Tensor.cs:28`. |
| `Dims` is public and mutable | **True.** The array is exposed. Its elements can be written through the property. |
| `ElementCount` is an unchecked product | **True.** `Dims.Aggregate(1L, (a, d) => a * d)` at line 31, recomputed on every call. The project does not enable `CheckForOverflowUnderflow`. |
| No dimension validation | **True.** Negative dimensions are accepted. |
| SharpMind stores ranks 1–4 inline | **True** for storage (`TensorShape.cs:21-27`, `:42-51`). |
| SharpMind rejects non-positive dimensions | **True** (`:34-37`, `:65-105`). |
| SharpMind uses int element counts | **True** (`ComputeElementCount`, `:411-417`). Stingray keeps `long`. |
| SharpMind avoids allocating for dimension access | **Partly wrong.** `Dims` and `Strides` allocate a fresh array on every call for ranks 1–4 (`CreateInlineDimsArray`, `:380-396`, and `:117`). The inline storage saves the stored arrays, not the accessor allocation. |

## 3. Contracts this must satisfy (what callers rely on)

Callers were counted by grep on 2026-11-09:
- **Construction**: about 2,445 sites in about 200 files under `src`, `tests`, `benchmarks`, `samples` and `tools`. They use `new TensorShape(long[])`, collection expressions such as `new TensorShape([asFloats.Length])` (an `int` widens to `long`), and `TensorShape.D1` to `D4`. Callers need these forms to keep compiling, and need valid values to keep working.
- **`Rank`** (`int`): used for branching.
- **`ElementCount`** (`long`): used to size allocations, so it must stay exact.
- **`Dims`**: read in about 16 files (for example `CpuBackend.cs`, `CudaSequenceKvCache.cs`, `QuantizedGpuUpload.cs`, `WanModel.cs`, `AudioGenGenerator.cs`, and several tests). Some of those are ONNX or GGUF `Dims` members, not `TensorShape`, and the compiler will separate them.
- **Equality and hashing**: no collection is keyed by `TensorShape` (grep found no `Dictionary<TensorShape>` or `HashSet<TensorShape>`).
- **Patterns and `with`**: no positional pattern, `Deconstruct` or `with` use on `TensorShape` was found.
- **`ToString`**: no test or message depends on the current output (the record default, `TensorShape { Dims = System.Int64[] }`).
- **`default(TensorShape)`**: not a valid shape. Using it throws `NullReferenceException` today, and this plan keeps that.

## 4. Behaviour map (member by member)

| Member | Current | After this change |
|---|---|---|
| Constructor `(long[] Dims)` | Stores the caller's array by reference. No checks. | Copies the array. Each dimension must be `>= 0`, otherwise `ArgumentOutOfRangeException`. The element count is computed once, with checked multiplication. Overflow throws `ArgumentOutOfRangeException`. |
| `Dims` | The writable array itself. | `ReadOnlySpan<long>` over the private copy. Callers that need an array call `.ToArray()`. |
| `Rank` | `Dims.Length` | `_dims.Length` (the same value). |
| `ElementCount` | Recomputed with unchecked `Aggregate`. | Cached field, computed in the constructor with checked math. |
| `D1` to `D4` | `new([...])` | Unchanged. They pass through the validating constructor. |
| `Equals`, `==`, `!=`, `GetHashCode` | Record equality compares the array by **reference**. Two shapes with equal dimensions compare unequal. | Value equality over the dimensions. The hash is computed over the dimensions. |
| `ToString` | Record default. | `(d0, d1, ...)`, for example `(2, 3, 4)`. Rank 0 gives `()`. |
| `Deconstruct` | Generated by the positional record. Exposes the array. | Removed. The compiler confirms no caller uses it. |

## 5. Decisions

- **D1. Zero dimensions are allowed.** SharpMind rejects them. Stingray does not, because zero-length tensors can arise at run time from computed sizes (for example `new TensorShape([nTok * rows])` with `nTok == 0`). Turning that into an exception would change a working path. Negative dimensions are always rejected.
- **D2. The 64-bit range is kept.** Dimensions stay `long`. A test covers a dimension beyond `int.MaxValue`.
- **D3. Inline storage for ranks 1–4 is not done.** The review's allocation saving has not been measured. The current design already allocates one array per shape, and inline storage would change the representation of a type with about 2,445 construction sites for no measured gain. CLAUDE.md rule 7 requires measurement before a performance change is kept, so this is deferred.
- **D4. `Dims` returns a read-only span, not an array.** This is the change that removes mutation. It costs call-site edits, which the compiler will list. Each edit is either `.ToArray()` (where an array is needed) or a loop.

## 6. Verification

- **New tests**, in `tests/OpenTail.Stingray.Tests.Core/TensorShapeTests.cs`:
  1. Mutating the original array after construction does not change `Dims`, `Rank` or `ElementCount`.
  2. A negative dimension throws `ArgumentOutOfRangeException`, through `D1`, `D2` and the array constructor.
  3. A zero dimension is accepted, with `ElementCount == 0`.
  4. Overflow throws: `D2(1L << 32, 1L << 32)`.
  5. A dimension beyond `int.MaxValue` is kept exactly: `D2(int.MaxValue + 1L, 4)` gives 2^33 = 8,589,934,592 elements.
  6. Rank 0 gives `ElementCount == 1`, and `ToString` gives `()`.
  7. Equal dimensions are equal: `==`, `Equals`, and equal hash codes. A `HashSet` finds an equal value.
  8. `ToString` gives `(2, 3, 4)`.
  9. `Dims` reflects the stored values, through a span.
  10. `ElementCount` matches the product for several ranks, and the existing `CoreTests` still pass.
- **Build**: `dotnet build OpenTail.Stingray.slnx -c Release`, which compiles every project, including the CUDA and Vulkan test projects. Warnings are errors in this repo.
- **Run**: `tests/OpenTail.Stingray.Tests.Core`, and `tests/OpenTail.Stingray.Tests.ForwardPass.Fast` (its CPU backend and SIMD tests build shapes heavily).
- **Not run here**: the CUDA and Vulkan test suites, which need a discrete GPU or a Vulkan device. The compile is checked; the behaviour is not.
- **Commit**: CLAUDE.md's owner rule is to commit and push to `origin/main` once the code works. Only the files this change touches are staged. The untracked Ollama plan and the untracked `docs/diffusion-samples/zz_flux2_prof.png` are not mine and are left alone.

## 7. Risks

- Code that relied on the writable `Dims` array will not compile. The compiler lists each case, so nothing fails silently.
- Code that relied on reference equality of shapes would change. No such code was found.
- A zero-dimension path that is currently accepted stays accepted (D1).
- **Extra allocation per construction (unmeasured).** The constructor copies its input, so each shape now makes one more small array than before. That is the price of the mutation fix. It runs against the review's allocation point, and no benchmark was run to size it. The alternative is a `ReadOnlySpan<long>` constructor, which removes the extra array (collection expressions targeting a span are stack-allocated). It would also turn a `null` array into a silent scalar, which is the kind of integrity problem this change exists to remove, so it is left as an owner choice. Measure before deciding.
