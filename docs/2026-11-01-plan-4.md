# Plan 4 (2026-11-01): what is worth doing next, checked against the code

Written after [plan 3](2026-10-31-autonomous-plan-3.md) ran out of items that can be done here. Source: the open boxes in the subfolders of `docs/`
(1-correctness, 2-coverage, 3-product-and-runtime, 4-performance, reference), about 395 unticked at the time of writing. Most of them are not work this
machine can do: they need CUDA or a discrete GPU, a second machine, a checkpoint that is not on disk, an owner decision, or they record ideas with no
owner. This plan keeps the ones that **name a failure, a user-visible limitation, a measurable gain or a recurring cost**, that can be done and
verified on this machine, and where the claim in the old box was **checked against the code first** (the "Checked" lines).

Contracts this must satisfy: perf claims need a quiet machine, interleaved A/B, 3+ runs and equal output (rule 7); real-weight tests are timed (rule 12);
numerics changes are gated by perplexity against llama.cpp and recorded in an ADR; a new test is mutation-checked; every item ends in its own merged PR.
