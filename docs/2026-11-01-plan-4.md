# Plan 4 (2026-11-01): what is worth doing next, checked against the code

Written after [plan 3](2026-10-31-autonomous-plan-3.md) ran out of items that can be done here. Source: the open boxes in the subfolders of `docs/`
(1-correctness, 2-coverage, 3-product-and-runtime, 4-performance, reference), about 395 unticked at the time of writing. Most of them are not work this
machine can do: they need CUDA or a discrete GPU, a second machine, a checkpoint that is not on disk, an owner decision, or they record ideas with no
owner. This plan keeps the ones that **name a failure, a user-visible limitation, a measurable gain or a recurring cost**, that can be done and
verified on this machine, and where the claim in the old box was **checked against the code first** (the "Checked" lines).

Contracts this must satisfy: perf claims need a quiet machine, interleaved A/B, 3+ runs and equal output (rule 7); real-weight tests are timed (rule 12);
numerics changes are gated by perplexity against llama.cpp and recorded in an ADR; a new test is mutation-checked; every item ends in its own merged PR.

## Checklist

### A. Numerics and engine

- [ ] **A1** Q3_K prefill and decode quantise activations differently. *Checked 2026-11-01:* `SimdKernels.TryResolveQ8Dispatch` maps `Q3_K` to `QuantizeRowToQ8KS`
  (eight scales per 256) for the batched path, while the single-token decode dot is `DotQ3K_Q8K` (one scale per 256); ggml uses one scale for both. Done when the
  Q3_K batched path uses the same activation format as decode (or the difference is measured to be harmless), judged by perplexity on Granite-Vision-3.2-2B Q3_K_S
  (llama.cpp reference 617.1 from perf-sweep 10.2) and prefill speed, with an ADR note. Source box: prefill-numerics follow-ups.
- [ ] **A2** MoE: quantise the token activations once before expert dispatch instead of per expert bucket. *Not yet checked:* read the batched MoE path first and write
  down what it does today; the box was written from memory. Done when the current behaviour is recorded and, if it quantises per bucket, the change is measured on
  Granite-4-H-Small (speed and PPL).
- [ ] **A3** Decide `STINGRAY_MOE_PREFILL_Q8` (default off) from a re-run of the Granite-4-H-Small PPL/NLL comparison after A1 and A2. Recorded decision, not just a number.

### B. Product surface

- [ ] **B1** `stingray pull` keeps its own HTTP client. *Checked 2026-11-01:* `PullCommand.cs:61` builds `new HttpClient { Timeout = 10 min }` and parses listings with a
  comment-marked special case beside `HubClient.ParseRepo`, while `Core/Net/HubClient.cs` and `ExternalHttpClient` exist. Done when `pull` uses the shared client and
  parser, with the existing pull tests still passing and a test for the case the special path exists for.
- [ ] **B2** Docs-as-tests beyond links. *Checked 2026-11-01:* `DocumentationLinkTests` covers relative links, backticked repo paths in the entry-point docs and the
  development project map; nothing checks that a cited hash or evidence file exists, or that a STATUS row still names a test that exists. Done when a test fails when a
  STATUS row cites a test class or golden file that is gone.
- [ ] **B3** Task qualification as a command. The chat, speak and transcribe recipes were run by hand on 2026-11-01 (plan 3, Q6); there is no reproducible command. Done when
  one script runs the three tasks against the pinned catalog files in a temporary model home and config directory (`STINGRAY_MODEL_HOME`, `STINGRAY_CONFIG_DIR`, so the
  owner's settings are never touched) and prints a pass or fail per task. Lesson recorded: `models use` writes `%APPDATA%\stingray\favourites.json`.
- [ ] **B4** Library surface audits from the public-surface plan: A2 (ownership, disposal and lock-order protocol), A3 (misleading parameter options, the library
  counterpart of the server parameter audit) and A4 (interface conformance and incomplete-turn semantics). *Not yet checked:* each starts by reading the public types;
  each ends with findings and tests, like the server audits did (they found a 500 and a fake image endpoint).

### C. Server

- [x] **C1** `/v1/sessions/*` parameter audit, the last endpoint group the 2026-11-01 audit did not cover. **Done 2026-11-01:** the turn digest ignored `allowed_choices` (a retry with other choices came back as a replay) and `temperature` and `top_p` were unchecked; both fixed, see F7 in the audit. *Checked:* `/tokenize`, `/detokenize`, `/props`, `/status` and
  `/api/embed` were read the same day: missing payloads are 400 (tested), out-of-range token ids decode to empty (`GgufTokenizer.DecodeBytes`), the embedding alias shares the
  validated parser. No defect found there.
- [ ] **C2** The audio routes ignore `model` (the route always builds a `WhisperPipeline`) and do not validate `language`; `/v1/audio/speech` replaces a non-positive `speed`
  with 1.0; `/v1/rerank` has no `top_n` range check. Done when each is either refused with a 400 that names the field or documented as ignored with the reason. A `model`
  that selects a pipeline is a behaviour change and needs the owner.

## Not in this plan (blocked or owner-gated; the reason is on the line)

- CUDA and discrete-GPU items (CUDA `rope_freqs` and scale fields, CUDA later-turn handoff, CUDA partial offload, discrete-GPU measurements, CUDA receipts, the whole
  external-hardware queue): no NVIDIA hardware here.
- AVX-512 and ARM64 execution receipts: no such machine; the claim is corrected in the docs instead.
- A clean-machine install of the released package, and the unreproduced Qwen3-Coder NaN (0 in 52 runs since the sighting): need a second machine or an owner decision to stop hunting.
- Gemma 2 GPU soft-capping (plan 3, Q3) and connecting the HTTP image API to the real pipelines (plan 3, Q7): owner decisions.
- Ported-but-unverified families (DeepSeek-V4, GLM-5.x, MiniMax-H3, DiffusionGemma, Qwen3.8-Flash-Next and the rest of `ported-families-todo.md`): they need real checkpoints
  that are 70 GB or more, or do not exist for download here; rule 14 keeps them internal.
- Scout ideas in `docs/todo.md` (demand-ranked backlog, batch triage, shared goldens index) and the perf-sweep boxes that need a discrete GPU: ideas without an owner or a
  measurable gain; they stay where they are.
